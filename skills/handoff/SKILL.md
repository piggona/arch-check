# 交付文档生成（handoff）

## 触发条件

用户在一次研发/修复/脚本对话即将结束时，要求生成交付文档。
如果用户没有指定任务类型，**根据对话内容自动判断**。

## 第 1 步：判断任务类型

从对话中提取线索：

| 类型 | 线索特征 |
|---|---|
| **需求开发**（feature） | 新增文件、新模块、需求描述、用户故事、新表/新接口设计 |
| **Bug 修复**（bugfix） | 异常日志、报错堆栈、原因分析、"修"/"fix"/"问题"/"排查" |
| **小工具/脚本**（script） | 单文件脚本、CLI 工具、一次性数据处理、迁移脚本 |

如果线索不明确，**直接问用户**："本次属于 `feature` / `bugfix` / `script` 中的哪一种？"

## 第 2 步：收集信息

基于对话历史和工作区状态，用以下工具收集必要信息：

1. **git diff / git log**：确认变更范围、改动文件
2. **Read 关键文件**：理解实现逻辑
3. **对话回顾**：提取关键决策、讨论过程中否决的方案

## 第 3 步：按模板输出

---

### 模板 A：需求开发（feature）

```markdown
# [需求名称] 交付文档

## 概述
- **需求背景**：一句话描述为什么做这件事
- **变更范围**：涉及哪些模块/文件（列表）

## 实现逻辑

### 核心流程
[用自然语言描述主流程，配合简化的流程步骤说明。如果涉及多个阶段用有序列表。]

### 主要变量/数据结构
| 变量/结构 | 含义 | 所在文件 |
|---|---|---|

### 关键算法/逻辑
[描述核心算法思路，注明时间/空间复杂度（如有必要）]

## 依赖项

### 库表
| 表/集合 | 用途 | 新增/已有 |
|---|---|---|

### 中间件/外部服务
| 组件 | 用途 | 备注 |
|---|---|---|

### 第三方库
| 库名 | 版本 | 用途 |
|---|---|---|

## 配置与环境变量
[列出新增或修改的配置项]

## 注意事项
- [后续维护需要注意的点]
- [已知限制或待优化项，可引用 arch-debt 标记]
```

### 模板 B：Bug 修复（bugfix）

```markdown
# [Bug 标题] 修复文档

## 问题描述
- **现象**：用户/系统看到了什么
- **影响范围**：哪些场景/用户受影响
- **严重度**：P0-P3

## 排查过程

### 定位路径
1. [第一步做了什么，看了什么日志/指标]
2. [第二步缩小范围]
3. [最终定位到根因]

### 关键日志/Trace
```
[粘贴帮助定位问题的关键日志片段，脱敏处理]
```
- **trace_id**：xxx（可选，方便回溯）
- **时间窗口**：xxx

## 根因分析
[一段话说清楚为什么出了问题——错误逻辑是什么、在什么条件下触发]

## 修复方案
- **改动文件**：列出
- **修复逻辑**：[描述修复做了什么]
- **为什么这样修**：[如果有多种方案，说明选择理由]

## 验证
- [x] 本地复现 → 修复后不再复现
- [ ] 相关单测/集成测试（是否新增）
- [ ] 线上验证方式

## 防退化
- [是否需要加监控/告警]
- [是否有 arch-debt 标记相关遗留]
```

### 模板 C：小工具/脚本（script）

```markdown
# [脚本名称] 使用文档

## 使用场景
[一两句话说清楚：什么时候需要用这个脚本，解决什么问题]

## 用法

```bash
# 基本用法
[命令行示例]

# 带参数
[更多示例]
```

## 参数说明
| 参数 | 必填 | 默认值 | 说明 |
|---|---|---|---|

## 输入/输出
- **输入**：[数据来源、文件格式等]
- **输出**：[产出什么、写到哪里]

## 依赖与前置条件
- [需要什么环境、权限、配置]

## 注意事项
- [幂等性：重复执行是否安全]
- [性能：大数据量下的表现]
- [限制：已知的边界条件]
```

---

## 输出约束

1. **语言**：跟随对话语言（中文对话输出中文文档，英文同理）
2. **格式**：Markdown，直接输出到终端（用户可复制）
3. **文件**（如果用户要求保存）：写到项目根 `docs/handoff/` 或用户指定路径
4. **简洁**：填充模板时不写空值段——如果某一节没有相关内容则省略该节
5. **真实**：所有内容必须从对话历史和代码中提取，**不得编造或猜测**
6. **脱敏**：日志/trace 中的 token、密码、内网 IP 等必须脱敏
